# MCVar — только подтверждённые результаты и открытые границы

## Результаты на реальной PCU — OBSERVED_RUNTIME

Источники: `../PCU_PHASE14_AUDIT.md`, `experiments/pcu_baseline/console/`, `experiments/pcu_phase14/console/`, `../PCU_PHASE14_ALL_413_SCENARIOS.csv`.

- На PCU50.3 (Windows XP x86) выполнены два прогона: первый — 104 сценария (включая DDE), второй — 413 (104 базовых и 309 расширенных). Во втором зарегистрированы 252 сценария MCVar с 277 `ReadVar`-раундами. 261 вызов с `HRESULT=0`, 16 — `0x80020009`.
- В этих наблюдениях пакетные `ReadVar` от 1 до 20 элементов работали. Для 20 элементов медиана четырёх серий около 115 мс; приближение `t≈20.5+4.58N мс` относится **только к этой PCU/сессии**. Нет доказанного количества внутренних DDE вызовов или сетевых пакетов к NCU.
- По слотам в аудите: `Quality=192` — 2752, `Quality=0` — 74. Ошибка `0x81000303` 73 раза (тестовые неверные адреса), `0x85000903` — 1 раз для `/Channel/Parameter/R[u1,100]`. Общий `S_OK` не гарантирует GOOD для каждого элемента.
- `pTimeStamps`: `VT_ERROR` в 272 и `VT_EMPTY` в пяти не принятых вызовах. Источник времени значений для продакшен-коллектора недоказан.
- `CacheDevice=0/1/2`, SAFEARRAY с нижними границами, дубликаты, неверные адреса, повторные чтения проверялись: первичные доказательства находятся в логах. Реального выигрыша `CacheDevice` по сохранённой выборке уверенно не установлено.

## Reverse — PROVEN_STATIC с обязательными поправками

Первый документ для изучения: [`reverse/IMPORTANT_corrected_COM_lifetime_and_vtable.md`](reverse/IMPORTANT_corrected_COM_lifetime_and_vtable.md).

- Действительный старый непрерывный body `ReadVar` начинается около **`0x1000BC30`**; `0x1000BC74` — внутренний экспортно размеченный адрес, но не пролог. Новый образ имеет другие смещения; полная эквивалентность пока не доказана.
- Вызов старого `0x1000BDDC → 0x10014CBE` — часть **восстановления/освобождения COM lifetime**, не доказанный `StartRequest`/`MakeCB`. Старый `0x10014CE2` и новый `0x10014DEC` — косвенный dispatch жизненного цикла.
- Установлены две таблицы vptr старого образа `0x1002C5BC` и `0x1002C758`, входящие через +0x1c в `0x1000BC30`; их +4/+8 пути описаны в corrected документе. Конкретный runtime-выбор не зафиксирован.
- `0x10004E2E` (`call [edx+4]`) — **неразрешённый кандидат косвенного вызова**, но не доказанная отправка DDE. В старых отчётах встречается ошибочная подпись `0x10004E1D` как indirect edge; это прямой call. Не использовать её без повторной проверки байтов.
- Подтверждено наличие User32/DDE API в бинарнике, однако реальный граф `ReadVar → DDE/IPC → NCDDE` **не построен**. Не смешивать с результатами общего sequence counter.

Прямые байты и операции находятся в `reverse/raw_disassembly_and_xrefs.tar.gz` (`logs_asmb/consolidation_architect.asm`, другие файлы через `RAW_TRACE_MANIFEST.json`). Исторические отчёты phase9–12 сохранены как доказательная история, но в них встречаются устаревшие наименования функций.

## COM API, TypeLib и циклические подписки — PROVEN_STATIC_NAME_ONLY

- Присутствуют встроенные старые/новые ресурсы TypeLib с именами `ReadVar`, `ReadVarAsync`, `ReadVarCyclic`, `RemoveCyclicVariables`, callback-интерфейсов с `OnDataChanged` (`api/resources`, `api/COM_API_REFERENCE.md`). Есть `MCVar.Var2` с ATL/Apartment регистрацией.
- Точные объявления IID/DISPID, направления `[in]/[out]`, callback contract и реальная подписка **не доказаны**. Три TypeInfo-probe из Phase14 не стартовали.
- Рекомендуется автономное декодирование обоих `MSFT` TypeLib через `LoadTypeLibEx(REGKIND_NONE)`, затем один Windows STA COM клиент с message pump.

## SDK — только исторический прототип

`sdk/phase13_original/` НЕ готовый Siemens adapter: MockAdapter и scaffolding. Не использовать в production. Документированные дефекты старой версии: loss of last GOOD после BAD, старое значение помечается FRESH после ошибки транспорта, `observed_at` до реального чтения, `threading.Lock` не обеспечивает STA, polling создаёт отдельные потоки и допускает нулевой интервал. Эти ошибки требуют исправления до подключения реальной PCU.

## Следующие адресные исследования

1. Реальный `ReadVarAsync` / `ReadVarCyclic` с точной TypeInfo и наблюдаемым callback.
2. Однопоточный STA collector с корректным quality/error/freshness и reconnect.
3. Разрешить **реальное** vptr+4 в `0x10004E2E`, затем записать передачу, API аргументы и ответ NCDDE в одной runtime-трассе. Данные о счётчике сами по себе не доказывают маршрут.
4. Проверка корректности каталога сигналов на каждой NC конфигурации.
