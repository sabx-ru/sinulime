# SINUMERIK Read-Only Topology Discovery v0.9.4

Исправленная экспериментальная версия на основе v0.9.2 / CU hotfix v0.9.3.
Поставляется без Siemens Topo и не содержит операций записи на контроллер.
Используются только S7 Upload SDB и S7 ReadVar.

## Запуск на Windows

Требуется Python **3.12 или 3.13 x64**; `INSTALL.cmd` создаёт локальную `.venv` и устанавливает `python-snap7==2.0.2` через pip. Нужен доступ к TCP/102 и разрешение на тестирование NCU. Обязательна проверка на остановленном стенде / станке с согласованием с обслуживающим персоналом: долгий опрос создаёт нагрузку.

1. Распакуйте ZIP в отдельную папку.
2. `INSTALL.cmd` — создаёт локальную `.venv`, устанавливает зависимости и запускает тесты.
   В состав зависимостей входят `python-snap7==2.0.2` и `pytest>=8.0`.
3. `RUN_CHECK.cmd` — повторная проверка без подключения к станку.
4. `RUN_LIVE.cmd` — новый запуск по IP; создаст папку `runs/<UTC>`.
5. `RUN_RESUME.cmd` — продолжение из прежнего каталога, в том числе старых частичных выгрузок v0.9.2 (не переименовывайте и не смешивайте каталоги разных станков).

Пример командной строки:

```powershell
.\.venv\Scripts\python.exe -m topology092 live --host 192.168.55.152 --out runs\cnc152_trial
.\.venv\Scripts\python.exe -m topology092 live --host 192.168.55.152 --out runs\cnc152_trial --resume
```

При продолжении обязательно используется прежний IP и та же конфигурация `target/p978_cap`. Скрипт перечитывает SDB и контрольные MD для защиты от смешивания конфигураций разных моментов времени. Если оборудование поменялось — создайте новый снимок.

## Новая политика ошибок v0.9.4

- `MD13120` определяет **реальные** CU: после CU5/CU2 больше не пробуется CU6/CU3 ради перебора до 16.
- На каждый сбой ReadVar по умолчанию **три попытки** (первое чтение + 2 повтора). Между попытками закрываем проблемное соединение, переподключаемся и увеличиваем паузу (2 и 4 секунды по умолчанию).
- Неуспешный **адрес** фиксируется в `reads.jsonl`, однако следующие независимые параметры продолжают читаться. Обычные `item_error` — штатный отказ по параметру, а не транспортная ошибка.
- После **шести подряд непрочитанных адресов**, а не шести попыток, выполняется контрольное чтение ранее успешно полученного `MD13120` (при его отсутствии — известного `p0102`) с новым подключением и тремя попытками. Если контроль успешен и значение не изменилось, опрос продолжается.
- Если и контрольные запросы не удаются, сбор завершается как `INCOMPLETE` — с сохранением существующих данных. При изменении подтверждённого контрольного значения завершение обязательно (во избежание смешивания разных конфигураций).
- Если `p0102` одной CU не удалось прочитать, после чтения NCK выполняется дополнительная попытка, затем эта CU пропускается, но остальные CU читаются. Финальный статус `INCOMPLETE`.
- Топологические массивы после первого прохода повторно читают только отсутствующие слова. Массив с неполными словами или изменившейся длиной **не помечается завершённым** и не используется как полный граф. Обработка других CU продолжается.
- SDB Listing и каждый SDB Upload тоже повторяются до 3 раз с переподключением.
- `INCOMPLETE` означает: сбор дошёл до конца, **но какие-то данные получить не удалось**. Не путать с `COMPLETE`. Результаты не дорисовываются по догадке.

Опции (для нового и повторного запуска):

```powershell
--retries 2 --max-consecutive-errors 6 --health-retries 2 --reconnect-pause 2 --interval-ms 200 --timeout 8
```

`--retries 2` = всего **3** попытки на адрес. `--health-retries 2` = всего **3** свежие проверки здоровья NCU. Не рекомендуется бесконтрольно повышать значения: это увеличивает нагрузку и длительность при недоступном контроллере.

## Файлы и диагностика

Сохраняются `capture.json`, `readvar/reads.jsonl`, `readvar_result.json`, `sdb/SDB*.full.bin`, `sdb/sdb_reads.jsonl`, `summary.json`, `architecture.json` и результаты топологии (`axis_map.csv`, `components.csv`, `physical_edges.csv`, `typed_relations.csv`, `DRIVE_CLIQ.graphml`). Снимок обновляется после каждой CU и при завершении. `readvar_result.json` содержит `incomplete_reasons`, `unresolved_addresses`, число health-check и полученных ответов.

Если связь пропала: запустите `RUN_RESUME.cmd`, укажите ту же папку `runs/...` и тот же IP. Успешные чтения будут использованы повторно только после проверки SDB и идентичности станции. `Ctrl+C` сохраняет накопленный журнал.

Для пересборки модели без подключения:

```powershell
.\.venv\Scripts\python.exe -m topology092 offline --reads runs\cnc152_trial\readvar\reads.jsonl --sdb runs\cnc152_trial\sdb --out rebuilt
```

В архиве нет логов станков, файлов ARC или бинарных файлов Siemens. Реальное сетевое поведение следует подтвердить на стенде — локально проведены лишь тесты на имитациях и офлайн-реконструкция старых выгрузок.
