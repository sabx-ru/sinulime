# ADR-001: Layered read-only core and transport-neutral application contract

- **Status:** Accepted for Stage 1 design
- **Decision:** Separate acquisition, decoding, topology resolution, evidence, State Manager, persistence, and API adapters. Keep live/replay behind one application service and keep transport out of the core.
- **Tradeoff:** More adapters and mappings, but deterministic replay, migration safety, and testability.

# ADR-002: Evidence-gated topology and explicit endpoint union

- **Status:** Accepted for Stage 1 design
- **Decision:** A confirmed equipment relation requires endpoint identity, successful decode, `rule_id`, immutable `rule_version`, all rule-required reciprocal/selector checks, and conforming evidence with exact artifact refs. Otherwise use `reference_only` or `unresolved`. One endpoint union covers physical device, logical object, channel, port, and object; `port_id` is not universal. `CU_LINK` is a representation relation, not a cable.
- **Tradeoff:** Larger payloads and more unresolved results avoid false topology. The sparse-index rule requires original source indices; absent/ambiguous indices cannot be confirmed. The current implementation gap is a Stage 2 blocker and requires a contract test.

# ADR-003: Separate Actual and Target graphs

- **Status:** Accepted for Stage 1 design
- **Decision:** Actual and Target are separate required payloads (graph or explicit availability object) with independent evidence and record instances. `null` is not a valid unavailable representation. Reconciliation is separate and uses `same`, `added`, `removed`, `changed`, `unresolved`, and `not_comparable`; selector mismatch is never equality.
- **Tradeoff:** Duplicate traversal/storage, but safe drift detection and no accidental conflation.

# ADR-004: Immutable snapshots, secure replay, and filesystem-first persistence

- **Status:** Accepted for Stage 1 design
- **Decision:** Publish immutable content-addressed snapshots with monotonic revisions and opaque cursors. Replay defaults to artifact IDs; local paths require canonical allowlist validation and hash audit. API bind is loopback-only; non-loopback bind is rejected and audited as `REMOTE_BIND_REJECTED`. Expired or gapped event offsets return `RESYNC_REQUIRED`; event IDs are deduplication keys.
- **Tradeoff:** Storage and migration work, plus conservative security restrictions, in exchange for reproducibility, auditability, and safe reconnect semantics.

# ADR-005: Stable and provisional identity

- **Status:** Accepted for Stage 1 design
- **Decision:** Stable UUIDv5 names use the published `sinumerik-core` namespace, `v1`, installation identity, kind, and canonical sorted-key JSON source identity. Missing/ambiguous identity receives a snapshot-scoped provisional UUIDv5 and unresolved status. Promotion requires an explicit evidence-backed mapping retaining both IDs.
- **Tradeoff:** IDs remain provisional longer, but sorting accidents and silent identity changes are prevented.

# ADR-006: Legacy evidence migration

- **Status:** Accepted for Stage 1 design
- **Decision:** Existing `evidence.json` is treated as legacy/non-conforming until migrated. Generic source/parameter fields do not satisfy v1's evidence ID, exact artifact ref, endpoint identity, rule/version, observed value/absence, and quality requirements. A hash-only baseline manifest may be generated as an audit artifact without modifying captures.
- **Tradeoff:** Compatibility adapters must expose unresolved/reference-only results during migration; audit claims remain truthful.

# ADR-007: Schema-derived Stage 2 envelope validation

- **Status:** Accepted for Stage 2
- **Decision:** Validate complete actual/target graphs, reconciliation records, unresolved records, endpoints, and evidence gates in the core contract validator. The validator is self-contained and schema-derived; it does not claim full JSON Schema implementation when the optional dependency is unavailable.
- **Tradeoff:** The validator duplicates the normative required-field and endpoint branches, but offline replay remains usable without third-party packages.

# ADR-008: Method-bound API envelopes and explicit implementation gates

- **Status:** Accepted for Stage 3 design; implementation gates open
- **Decision:** Use method-specific request and response schema variants. Notifications omit `id` and never receive a response. Evidence has exactly one observation form, endpoint identity status is explicit, artifacts carry reproducibility metadata, and `RESYNC_REQUIRED` carries complete recovery data. Keep the published identity algorithm and sparse-source-index correction as explicit pre-implementation gates; do not weaken the contract to match divergent runtime code.
- **Tradeoff:** More schema branches and migration work, but machine validation cannot accept method/parameter confusion, ambiguous absence, unverifiable artifacts, or false topology confirmation.

# ADR-009: Separate installation identity from capture provenance

- **Status:** Accepted for bounded contract slice
- **Decision:** `InstallationIdentity` and `CaptureHostIdentity` are separate value objects and serialized fields. Installation identity is confirmed only from explicit trusted configuration/deployment metadata, explicit machine/plant IDs, or source-local IDs with declared scope/stability and evidence. Host, process, timestamp, and adapter describe capture provenance only.
- **Rules:** Missing installation sources remain unknown. Conflicting trusted sources remain an explicit conflict with source references. Legacy `installation_id` remains readable as a provisional adaptation and never becomes confirmed without evidence. Display names, host names, IPs, and `device_id` do not establish installation identity.
- **Scope:** Additive optional envelope fields only; no topology relationships, stable device IDs, acquisition, transport, live CNC, ARC, PDF, electrical drawing, or capture changes.
- **Tradeoff:** Consumers must handle unknown/provisional/conflict states, but replay and multi-host captures cannot silently merge installations.
