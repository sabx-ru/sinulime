# Topology Schema V1

**Schema:** `sinumerik-core/read-only-topology/v1`  
**Status:** normative design; machine-readable schema is `docs/schema/topology-v1.schema.json`  
**Legacy note:** existing v0.9.x `evidence.json` is non-conforming until migrated.

## Envelope

A v1 document has `schema`, `snapshot_id`, monotonic `revision`, RFC3339 UTC `captured_at`, `mode`, `installation_id`, `completeness`, `actual`, `target`, `reconciliation`, `evidence`, `unresolved`, and `extensions`. `actual` and `target` are separate payloads; an unavailable side uses `{ "availability": "unavailable", "reason": "..." }`. `null` is not valid for unavailable data. An empty graph means observed and complete with zero records, not missing data.

Statuses are `confirmed`, `reference_only`, `unresolved`, `incomplete`, and `not_comparable`. `probable` is a confidence label only and never authorizes a confirmed edge.

## Records and endpoint union

The JSON Schema is authoritative for required properties, nullability, enums, recursive extensions, and `additionalProperties`. IDs are opaque strings to clients. A connection uses the same endpoint union everywhere:

```json
{"id":"conn-1","kind":"DRIVE_CLIQ_CABLE","from":{"object_id":"port-a","kind":"port","selector":{"group":1,"ordinal":0}},"to":{"object_id":"port-b","kind":"port","selector":{"group":1,"ordinal":2}},"status":"confirmed","confidence":"confirmed","rule_id":"reciprocal_component_group1","rule_version":"1.0.0","checks":["reciprocal_peer","selector_match"],"evidence_ids":["ev-1"],"extensions":{}}
```

Each endpoint kind has a machine-readable selector branch: `physical_device.device_key`, `logical_object.logical_key`, `channel.channel_kind` plus `ordinal`, `port.group` plus `ordinal`, or generic `object.object_key`. `port_id` is not required for other endpoint kinds. `physical_device`, `logical_object`, `channel`, `port`, and generic `object` are distinct. A `CU_LINK` is a `relation` of kind `representation` between one physical device and its representations; it is not a cable `Connection`.

## Evidence gate

Evidence requires `evidence_id`, `artifact_id`, exact `artifact_ref` (raw observation locator or artifact member/byte range), `endpoint_identity`, `observed_value` or explicit `observed_absent`, `observed_at`, `quality`, `rule_id`, and `rule_version`. Confirmed equipment relations, including `representation`/`CU_LINK`, require endpoint identities, decoder success, `rule_id`, immutable `rule_version`, one or more named `checks`, and one or more evidence IDs resolving to conforming evidence. Otherwise use `reference_only` if a source exists, else `unresolved`.

Stage 2 implementation gate: the current sparse sensor implementation remains blocking and must be fixed and covered by a contract test before any Stage 1 implementation-ready verdict. For sparse sensor arrays, `artifact_ref.source_ref.index` is the original source index. It must not be regenerated by enumeration after filtering. Missing, duplicate, or ambiguous original indices force `unresolved` with `ambiguous_mapping`.

## Actual/Target reconciliation

Reconciliation compares independent payloads and reports `same`, `added`, `removed`, `changed`, `unresolved`, or `not_comparable`. Target-only is `added`; actual-only is `removed`; selector mismatch is `not_comparable` with `selector_mismatch`; absent evidence is `unresolved`. Equality is never inferred from equal counts.

Measured examples only: cnc135 has 58/58 physical edges and 4 CU_LINK pairs; cnc152 has 13/13 and 1. These are fixture observations, not schema defaults.

## Compatibility and migration

The v1 adapter may read legacy JSON/CSV and preserve unknown fields under `extensions`, but missing v1 identity/evidence fields produce unresolved or reference-only results. Legacy generic refs (`source`, `parameter`) do not satisfy v1. PDF, electrical drawings, and ARC comparison remain external corroboration and cannot create a runtime edge.
